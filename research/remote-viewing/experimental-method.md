# Experimental Method

This document turns remote-viewing practice into an auditable experiment. It is deliberately stricter than casual training because free-response data are easy to overinterpret.

## 1. Define the exact claim first

Do not start with “remote viewing works.” Choose one claim.

Examples:

- **Target-ranking claim:** locked transcripts rank their assigned targets above chance among four candidates.
- **Feature claim:** preregistered target features are identified above a randomization baseline.
- **Training claim:** CRV training improves held-out target performance more than matched descriptive-observation training.
- **Sender claim:** sender-present trials outperform no-sender trials.
- **Precognition claim:** transcripts locked before target selection correspond to the later random target.
- **Ensemble claim:** an aggregation rule fixed in advance improves out-of-sample accuracy over one viewer.
- **Operational-specificity claim:** viewers identify a low-base-rate fact useful to a blinded decision maker, not merely broad gestalt.

Each requires a different design.

## 2. Pre-registration contract

Before the first viewer receives a cue, freeze:

- research question and directional or non-directional hypothesis;
- primary outcome;
- sample size and stop rule;
- target universe and candidate-set construction;
- randomization algorithm and seed/receipt policy;
- blinding roles;
- viewer inclusion and training criteria;
- abort and exclusion rules;
- transcript format and lock procedure;
- judging rubric;
- analysis model;
- multiple-comparison correction;
- treatment of missing data;
- confirmatory versus exploratory outputs;
- publication commitment, including null results.

Timestamp the registration in a system not controlled by the analyst. A Git commit can supplement—but should not replace—an external preregistration for a consequential study.

## 3. Units and identifiers

Use distinct opaque IDs for:

- study;
- cohort;
- viewer;
- session;
- target;
- candidate set;
- randomization event;
- transcript lock;
- judge;
- analysis run.

Never encode target class or correct-candidate position in a session ID.

Recommended pattern:

```text
study_id: RV-CRV-CONTROL-2026-01
viewer_id: V-014
session_id: S-000184
cue: 7314-9082
candidate_set_id: CSET-000184
judge_id: J-03
```

The cue is an arbitrary task handle, not evidence that geographic coordinates carry information.

## 4. Target design

### 4.1 Fix the target object

Specify whether the target is:

- an exact image;
- a video segment with fixed start and end;
- a physical location at a defined time;
- a physical object;
- a future feedback image;
- an event with a fixed observation window.

“Eiffel Tower” is underspecified. An exact photograph, viewpoint, time, and intended target aspect are better.

### 4.2 Target entropy and distinctiveness

A good pool has:

- strong between-target differences;
- controlled within-target complexity;
- balanced salience and emotional intensity;
- no duplicate dominant gestalts within a candidate set;
- no target-specific metadata leakage;
- enough items that viewers cannot memorize the pool;
- targets that admit reliable feature coding.

Record a target-feature vector before sessions begin. Example dimensions:

```text
natural / built
water present
enclosed
dominant vertical
dominant circular
biological density
motion intensity
temperature cue
metallic
open horizon
luminous / dark
```

Feature coding must be performed blind to session results.

### 4.3 Candidate-set construction

The correct target and decoys must be comparable. Do not place one waterfall among three office interiors and celebrate “water.”

Options:

- random decoys drawn under a stratified rule;
- matched decoys with similar salience and complexity but different gestalt;
- balanced Latin-square use of candidates so each target appears as correct and decoy across the study.

Fix the construction rule before data collection.

## 5. Randomization and commitment

Randomization should be:

- generated by a documented algorithm;
- unpredictable before assignment;
- immutable after assignment;
- independently auditable;
- separated from the viewer and monitor.

A commitment binds the manager to a target without revealing it:

```text
commitment = SHA-256(random_nonce || canonical_target_record)
```

The nonce prevents easy brute-force discovery when the target pool is small. At reveal, publish the nonce and canonical target record so anyone can recompute the hash.

The included target manager implements this integrity pattern. It is not an encryption system: the private assignment still must be access-controlled.

### Target-before versus target-after

- **Target-before:** assignment and commitment happen before the session. Suitable for direct-target or sender tests.
- **Target-after:** transcript is locked before random target selection. Suitable for precognition/future-feedback tests.

Do not mix the two in analysis.

## 6. Blinding matrix

| Role | Must not know before transcript lock |
|---|---|
| Viewer | target identity, candidate set, correct position, target class, study arm when practical |
| Monitor | everything the viewer does not know |
| Target manager | may know target but must not interact with viewer or judge |
| Judge | correct candidate and assignment; ideally viewer identity and condition |
| Analyst | condition labels during primary pipeline development when practical |
| Feedback operator | may know after all judgment is fixed |

Document every unavoidable exception.

### Blinding audit

After each block, ask each role to guess:

- target class;
- correct candidate;
- study arm;
- whether the trial was expected to succeed.

Above-chance guesses can reveal leakage even when no one reports conscious cueing.

## 7. Transcript integrity

The raw transcript includes:

- every written page;
- sketches and models;
- audio/video if used;
- start/end timestamps;
- prompts;
- monitor statements;
- breaks;
- page order;
- confidence ratings;
- protocol deviations.

Before feedback:

1. convert to a stable file or archive;
2. compute SHA-256;
3. store the hash and byte length;
4. timestamp the lock;
5. make the raw layer append-only.

A typed transcription is derivative. Preserve the handwritten or original digital artifact and record any transcription uncertainty.

### Transcript sanitation for judging

Create a judging copy that removes:

- session date;
- cue order;
- page headers that identify target set;
- target-manager notes;
- feedback-class markings;
- filenames;
- viewer names;
- comments written after reveal.

Record the hash of both raw and sanitized copies and the deterministic transformation, when possible.

## 8. Judging designs

### 8.1 Rank-order judging

A judge ranks the candidate targets by correspondence with the transcript.

Primary outcomes can be:

- rank of actual target;
- top-1 hit;
- sum of ranks across trials;
- standardized rank statistic under the exact randomization.

Strength: simple and historically comparable.

Weakness: depends on candidate-set construction and judge interpretation.

### 8.2 Feature-vector scoring

Before sessions, code each target on fixed features. Blind coders then code each transcript using the same ontology. Similarity is computed by a locked algorithm.

Strength: reduces unconstrained narrative matching.

Weakness: feature ontology can omit distinctive information or encode analyst assumptions.

### 8.3 Independent qualitative review

A blinded expert writes a narrative assessment before learning target identity.

Useful for understanding failure modes, but should be secondary unless a scoring rule is fixed.

### 8.4 Operational decision task

A blinded decision maker chooses among predefined actions using the viewer output.

This tests utility rather than mere correspondence. It must include the cost of false positives and compare against a no-RV baseline. Do not attempt it until laboratory reliability exists.

## 9. Statistical plan

### 9.1 Four-choice top-rank outcome

If each trial has four symmetric candidates, the chance probability of a top-rank hit is 0.25.

For `n` independent trials with `h` hits, an exact one-sided binomial tail is:

```text
P(H ≥ h | n, p = 0.25)
```

Independence is often violated when the same viewer, judge, target, or pool recurs. A simple binomial test should not be the only analysis.

### 9.2 Rank outcome

With `k` candidates, random expected rank is:

```text
(k + 1) / 2
```

Use a permutation or randomization test that mirrors the assignment and candidate-set process. This is preferable to assuming normality for small samples.

### 9.3 Hierarchical structure

A serious programme should estimate separate variability for:

- viewer;
- target;
- judge;
- laboratory;
- session order;
- protocol condition.

A positive average carried by one viewer or one target pool is not broad replication.

### 9.4 Effect size and uncertainty

Report:

- raw hit rate or mean rank;
- chance expectation;
- absolute difference;
- confidence or credible interval;
- preregistered effect size;
- all sensitivity analyses;
- complete trial count and exclusions.

A small p-value does not tell the mechanism, practical usefulness, or probability that the paranormal hypothesis is true.

### 9.5 Sequential testing

Do not check significance after every session and stop when it becomes favourable. Use:

- fixed sample size; or
- a preregistered sequential design with explicit error control.

### 9.6 Multiple outcomes

Choose one primary outcome. Mark the rest exploratory or correct for multiplicity.

## 10. Sample-size thinking

The sample size depends on the smallest effect worth detecting, expected viewer and judge variation, design power, and error rates. Historical effect sizes should not be copied uncritically into a new protocol.

Use three stages:

1. **engineering pilot:** 10–20 sessions to verify workflow; no efficacy claim;
2. **estimation pilot:** enough trials to estimate variance and judge agreement;
3. **confirmatory study:** sample size computed from the preregistered meaningful effect using held-out assumptions.

One viewer doing hundreds of trials estimates that viewer-system combination. It does not by itself establish population-level trainability.

## 11. CRV training comparison

To test whether CRV structure contributes beyond attention and descriptive practice, randomize participants to:

- CRV training;
- matched-duration observational-description training;
- optional wait-list or minimal-instruction control.

Match:

- instructor contact;
- practice volume;
- feedback frequency;
- motivation;
- expectations;
- target exposure;
- test environment.

Use a held-out target pool and blind judges. The primary test is the difference in change, not whether the CRV group alone is above chance.

## 12. Multiple-viewer aggregation

Multiple viewers do not create independence if they discuss the target or train on the same tiny pool.

A valid ensemble rule is fixed before reveal:

- majority vote on candidate rank;
- median candidate rank;
- weighted average using weights learned only on prior data;
- feature consensus requiring independent overlap;
- Bayesian or machine-learning aggregator trained and frozen on a separate cohort.

Evaluate the ensemble on held-out sessions. Compare with:

- best single viewer chosen prospectively;
- average individual;
- random baseline;
- a non-RV descriptive-control group.

Never tune weights on the trials used to claim ensemble success.

## 13. AI use

AI can assist with:

- redacting transcript metadata;
- extracting preregistered descriptors;
- applying a frozen feature ontology;
- checking protocol compliance;
- aggregating independent sessions under a locked rule;
- finding source records.

AI must not:

- see the correct target while scoring;
- rewrite transcripts;
- invent missing session content;
- choose favourable decoys after seeing a transcript;
- silently tune prompts until the answer matches;
- convert vague output into a confident operational claim.

Store model name/version, prompt, settings, input hash, output, and all retries. A human-selected “best AI interpretation” is another flexible judge.

## 14. Adversarial controls

A strong study includes controls designed to catch the research team.

### Sham-target trials

Run identical sessions where no target is assigned until after judging, or where the assignment deliberately points to a null record. Predeclare interpretation.

### Transcript swaps

Judge some transcripts against the wrong candidate sets. If judges still report impressive matches, the rubric is too flexible.

### Decoy viewers

Include descriptive text generated without viewing under matched word count and style.

### Leakage team

Give an independent reviewer only the workflow and artifacts and ask them to infer target identity through metadata or procedure.

### Negative-control features

Include target attributes that should not be inferable from generic imagery. A scoring system that awards them frequently is overpermissive.

A session ledger should minimally contain:

```json
{
  "study_id": "RV-CRV-CONTROL-2026-01",
  "session_id": "S-000184",
  "viewer_id": "V-014",
  "cue": "7314-9082",
  "assigned_at": "2026-08-07T01:02:03Z",
  "target_commitment": "sha256:...",
  "condition": "masked-until-analysis",
  "transcript_sha256": "...",
  "locked_at": "2026-08-07T01:31:19Z",
  "candidate_set_id": "CSET-000184",
  "judge_ranks": {
    "J-01": ["T-09", "T-14", "T-22", "T-03"],

  },
  "revealed_target_id": "T-09",
  "deviations": [],
  "status": "complete"

```

Private target information and personal data should live outside a public repository. Publish de-identified receipts and aggregate data only when consent and rights allow.

## 16. Protocol deviations

Classify before seeing results where possible:

- **minor:** timer drift, non-substantive formatting issue;
- **major:** monitor learned target class, incomplete transcript capture, target pool exposed;
- **fatal:** viewer knew target, assignment changed, transcript edited after reveal, judge knew correct answer.

Do not automatically delete major or fatal trials. Preserve them, exclude them from the confirmatory analysis under the preregistered rule, and report both counts.

## 17. Replication ladder

1. same viewer, same manager, same pool;
2. same viewer, new manager and held-out pool;
3. new viewer, same laboratory;
4. independent analyst re-scores frozen artifacts;
5. independent laboratory runs shared protocol and code;
6. adversarial collaboration with proponents and critics agreeing in advance;
7. registered multi-lab report with pooled and site-specific results.

Claims should rise only as the evidence climbs the ladder.

## 18. Interpretation matrix

| Result | What it supports | What it does not establish |
|---|---|---|
| Chance-level pilot | workflow may function; no detected effect | impossibility of all remote viewing |
| Above-chance rank, one viewer | anomaly in that viewer-system block | mechanism, general trainability, operational use |
| Multi-viewer, independent replication | broader reproducibility under that protocol | Matrix, signal line, clairvoyance rather than precognition |
| Sender advantage | sender condition matters | telepathy unless ordinary sender leakage is excluded |
| Target-after-lock success | future-target correspondence under design | direction of causation or physics |
| Strong broad gestalt, poor specifics | coarse correspondence | actionable intelligence |
| High confidence, poor score | miscalibration | absence of all low-confidence signal |
| AI improves scoring only after prompt tuning | analyst flexibility | viewer accuracy |

## 19. Release gate for a study

A study result is ready for Great Library registration only when:

- protocol and analysis were fixed before reveal;
- target assignments and transcript locks verify;
- every initiated session has a status;
- raw and sanitized artifacts are preserved under a rights-safe policy;
- candidate construction and judge blinding are documented;
- code reproduces tables from the frozen data;
- deviations and exclusions are complete;
- confirmatory and exploratory claims are separated;
- an independent person reruns the analysis;
- the release states exactly what was and was not demonstrated.

The objective is not to make remote viewing look good or bad. It is to make the result difficult to fool.
